# Запрос в Коммерсантик: оставшиеся пробелы для блога aitishka.pro

Проверено после фаз **A–G** в репозитории `shop` (миграции `0023`–`0026`).
Заявки, CMS-статьи/рубрики (`parent_id`, фильтры, SEO OG/canonical), импорт/экспорт статей и рубрик, плейлисты (embed), `storefront_extra`, sitemap и schema блоков — **уже есть**.

Ниже — только то, чего **ещё нет**, но нужно для нормального управления образовательным блогом (не путать с доработкой витрины `aitishka-pro`).

---

## 1. Согласовать контракт `POST /api/requests`

В коде публичного handler поле имени — `name` (`json:"name"`).
В `docs/integrations.md` указано `customer_name`.

Нужно: принимать оба варианта **или** поправить документацию под `name`. Иначе заявки с витрины/интеграций по доке молча ломаются на валидации контакта.

---

## 2. Фильтр статей по родительской рубрике (с потомками)

Сейчас `GET /api/cms/articles?category=<slug|id>` — **точное** совпадение.
У aitishka иерархия «Для взрослых → Python»: статьи обычно висят на **дочерней** рубрике. Фильтр по родителю не отдаёт их.

Нужно: режим вроде `category=<parent>&include_children=1` (или поведение по умолчанию для родителя — включать subtree). Без этого навигация по верхнему уровню в панели превью/на витрине бесполезна.

---

## 3. Импорт / экспорт CMS-страниц (`cms_pages`)

Статьи и рубрики экспортируются; **страницы** (О нас, Политика, Соглашение, лендинги) — нет.

Нужно: тот же JSON-паттерн, что у статей (`/api/admin/pages/export|import`), чтобы перенести `/about`, `/privacy`, `/terms` и править их только в панели.

---

## 4. Импорт / экспорт видеоплейлистов

Плейлисты (VK/YouTube/Rutube) управляются в панели, но **нет** export/import.
На aitishka сейчас каталог в `content/videos.json` — разовый перенос и бэкап плейлистов без UI-кликов по одному.

Нужно: `/api/admin/playlists/export|import` (slug, title, status, ролики с embed URL/provider, порядок) + кнопки в списке плейлистов.

---

## 5. (Желательно) Конвертер `content_md` → `content_blocks` при импорте статей

Импорт статей уже принимает `content_md` и `content_blocks`. Для миграции ~55 markdown-постов удобнее опция `?blocks_from_md=1` (или чекбокс в UI): после upsert тело сразу в блочном редакторе, а не только как MD-fallback.

Не блокирует запуск, но сильно упрощает повседневное редактирование после переноса.
